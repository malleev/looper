# Orange Pi Guitar Looper — однодорожечный MVP

C++17, ALSA, Orange Pi PC (H3, 1 ГБ RAM), MiniFuse 1. Сейчас реализована одна
моно-петля: выбранный входной канал, одинаковый звук в выходах L/R. Цель этого
этапа — надёжная запись одной дорожки; многодорожечность, MIDI и эффекты позже.

## Сборка на плате

```sh
cd ~/looper
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release -DENABLE_ASAN=OFF
cmake --build build -j2
ctest --test-dir build --output-on-failure
./build/looper
```

Также поддерживаются `make -j2` и `make test`.

## Память и задержка

По умолчанию приложение резервирует **60 секунд** записи: три mono float32
буфера (база, последний слой Undo, новый overdub), всего **34,56 МБ** плюс
небольшие служебные расходы. При загрузке WAV временно нужны старые и новые
буферы; сохранение требует дополнительного снимка длиной с петлю.

```sh
./looper --max-seconds 60
./looper --max-seconds 300
```

Пять минут требуют 172,8 МБ только для трёх основных буферов. Это ёмкость
записи, не задержка: ALSA использует 128 кадров на период и 512 кадров всего
при 48 кГц (2,67 и 10,67 мс соответственно). Полную задержку вход→выход нужно
измерять отдельно. По достижении ёмкости запись автоматически переходит в Play.

## Управление

| Клавиша | Действие |
|---|---|
| Пробел | Record → Play → Overdub → Play; из Stop продолжить |
| S | Stop |
| C | Очистить петлю |
| U | Undo/Redo последнего завершённого overdub |
| R | Reverse |
| F | Затухание до остановки за 3 секунды |
| M | Переключить Software / Analog мониторинг |
| W | Сохранить WAV; сначала остановить S |
| L | Загрузить последний WAV из recordings/; текущая петля заменяется |
| > / < | Компенсация задержки ±32 сэмпла |
| + / - | Громкость петли |
| Q | Выход; несохранённая петля теряется |

USB-клавиатура определяется при запуске. В SSH нужен интерактивный терминал.
Reverse, Undo и изменение мониторинга/компенсации блокируются во время overdub.

## Аудио

- По умолчанию **Software**: dry включён, компенсация overdub K=0.
- `--monitor analog`: dry выключен, требуется аппаратный прямой мониторинг;
  K по умолчанию 384 сэмпла. Это исходная настройка, не подтверждённая
  калибровка конкретного подключения. `--latency N` меняет её.
- Pre-roll 256 сэмплов; при ручном завершении записи длина компенсируется.
- Стык базы и завершённого overdub корректируется на участках до 5 мс с двух
  сторон, без изменения длины. Это изменяет звук около стыка; слуховая проверка
  на реальном материале обязательна. Во время активного overdub слой изменяется
  в реальном времени, поэтому абсолютное отсутствие переходных щелчков не обещается.
- Внутреннее суммирование float32; выход ограничивается жёстким клиппингом.
  Это защита диапазона PCM, **не динамический лимитер**.
- WAV сохраняется атомарно через временный файл, fsync и rename, в **mono
  float32** с сохранением headroom. Поддерживается импорт PCM16/24/32 и float32
  48 кГц. Из многоканального файла берётся первый канал. Повреждённые, пустые,
  нечисловые и слишком длинные данные отклоняются. WAV хранит сведённый звук,
  а не историю Undo или настройки сессии.

Аудиопоток использует предварительно выделенные буферы и SPSC-очереди; дисковый
ввод/вывод вынесен в worker. Движок обрабатывает команды внутри блока.
Привязка блока использует монотонную отметку ALSA и оставшиеся в capture кадры:
[ALSA status API](https://www.alsa-project.org/alsa-doc/alsa-lib/group___p_c_m___status.html).
Поздно доставленное событие невозможно применить к уже выданному звуку; оно
применяется на начале доступного блока. SSH не обеспечивает точность физической педали.
Память не заблокирована через mlock; SCHED_FIFO зависит от прав пользователя.

## Проверки

Release-тесты сохраняют assert включёнными. Для настоящего ASan/UBSan:

```sh
cmake -S . -B build_asan -DCMAKE_BUILD_TYPE=Debug -DENABLE_ASAN=ON
cmake --build build_asan -j2
ASAN_OPTIONS=detect_leaks=1:halt_on_error=1 UBSAN_OPTIONS=halt_on_error=1 ctest --test-dir build_asan --output-on-failure
```

`looper_tests` — исходные 23 сценария. `looper_regressions` — проверки пиков PCM,
времени блока с накоплением кадров, мониторинга, fade, стыков, лимита записи,
отложенных команд, WAV и реальной ошибки короткой записи с сохранением старого файла.

Опциональный тест через настоящую звуковую карту (она должна быть свободна):

```sh
python3 test/hardware_smoke.py build/looper
```

Он кратко записывает физический вход, проверяет управление и WAV, оставляя
результаты в отдельном каталоге внутри build. Калибровочные импульсы не посылает.
`--calibrate` требует отдельного физического кабеля OUT1→IN1 и запуска вручную.
Короткий тест не заменяет длительную проверку на репетиции. Автоматическое
переподключение звуковой карты и восстановление сессии пока не реализованы.
